# 受限执行环境兼容方案（待审阅）

当前版本继续在本机解释器的子进程中执行可信代码，默认 6 秒超时。Python 的 -I 只隔离部分解释器配置。当前没有 OS 内存配额，也没有文件、网络或子进程访问隔离。本次没有启用或部署新的执行环境。

## 拟议边界

S1 迭代已接通显式后端选择和有界本地传输。输入上限 2 MiB，stdout 上限 32 MiB，stderr 上限 64 KiB；只在 trusted 模式启动本地解释器。isolated 当前始终拒绝执行。主机检查为 Windows NT 10.0.26200，PATH 中有 wsl.exe，未发现 docker 或 podman 命令；没有验证 Linux 发行版已配置。未部署容器，因此目前没有容器资源占用、冷启动或清理的实测结果。

为 Windows 主机提供单独的可选运行后端，在预先配置的无网络 Linux 容器内运行相同版本的 runner。保留可信本地模式；未配置隔离后端时，对要求隔离的任务直接报告不可用。切换必须显式选择，不自动降级。替换边界仅为 run_isolated 的载荷传输；GUI、教学检查器、World、checkpoint、返回 JSON 与回放保持兼容。

隔离镜像仅含固定的 Python 与游戏运行模块。以非 root 身份运行，只读根文件系统，无宿主路径挂载、无设备或控制套接字、无网络、移除 capabilities，并采用宿主支持的系统调用策略。对整个进程组设置内存、进程数、CPU、墙钟时间和标准流字节上限。宿主负责杀死并清理整个实例。若后端不能确认这些限制，则拒绝启动。

原型启动前还应核对镜像内容摘要（固定 digest）、禁用交换或设置明确的内存与交换总量上限、核对 seccomp 配置和有效挂载列表。逐条验证实际配置，记录启动到首个结果的时间、峰值内存、清理后实例数量。容器使用共享内核，隔离效果需独立审阅。

## 审阅后才实施

1. 确认目标 Windows 版本及可用容器运行时。安装、虚拟化设置、镜像下载和任何主机权限变更均需单独授权。
2. 通过 stdin/stdout 传送限长 JSON。保留标准库及现有参考算法；依赖用户本机文件、环境变量、网络、第三方包的旧程序只能在可信模式使用。
3. 对两个后端运行相同的历史参考、Unicode、超时、异常、十事件和 Tk 测试。额外验证宿主文件不可见、出站网络不可用、派生进程受限、内存超限可回收，以及异常退出后 GUI 可重试。
4. 记录冷启动时间、峰值内存、有效配置与容器清理情况，独立通过审阅后再开放执行不可信代码。
