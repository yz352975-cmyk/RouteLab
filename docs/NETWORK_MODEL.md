# 真实网络原理与游戏简化

本版是一个真正通过延迟消息驱动的距离向量教学模型，不是完整的 RIP、OSPF 或 BGP 实现。参考算法在玩家 Python 中执行；仿真器负责运输消息、物理事件、转发和观察器验收。

## 所演示的真实原理

- 每台路由器只用本地链路与邻居的距离向量，按 Bellman–Ford 的局部关系更新距离：`D_x(d) = min_v(cost(x,v) + advertised_v(d))`。
- 故障不会瞬间刷新全网。过时通告可以使路由器互相依赖，出现转发环路与计数到无穷；坏消息也必须允许距离增加。
- 反向毒化把经某邻居学到的路由以不可达通告回该邻居，可处理两路由器相互依赖；仍可能发生更长的环路，触发更新也不提供普遍无环保证。
- 数据包的 TTL 限制环路中的存活跳数，它本身不修复控制面。

距离向量、计数到无穷及反向毒化的参考：[RFC 2453 §3.4、§3.4.2–3.4.4](https://www.rfc-editor.org/rfc/rfc2453.html)。本项目有一个三节点瞬态环路测试，明确防止把反向毒化描述成万能解法。

## 逐项区别

| 项目 | 本游戏的明确机制 | 与真实部署的区别 |
|---|---|---|
| 地址和拓扑 | 七个字母节点；全局开场保留原拓扑，随后使用有廉价分支和备用路径的环形拓扑 | 没有 IP 地址、子网、前缀汇总、自治系统或路由重分发 |
| 路由表 | 对节点地址维护距离与下一跳；目标固定 F | 真实路由一般针对网络前缀，可能有多协议优先级、ECMP 等 |
| 代价与无穷 | 自选加权链路；度量上界 16；达到 16 即不可达 | 借用 RIP 的无穷值概念；不是链路时延测量，也不等同于一般 IP 跳数 |
| 消息传输 | 显式事件队列，至少延迟 1 时隙，可变延迟产生乱序；相同到达时间 FIFO | 没有 UDP/IP 报文格式、带宽、拥塞、MTU、控制消息随机丢失或真实设备 |
| 时间 | 虚拟整数时隙；程序运行时推进，编辑时冻结；默认周期 4、缓存建议超时 `12 + 2D` | 与真实秒数无换算；RIP 的实际周期/计时器请见 RFC 2453 §3.8，本项目不实现其完整计时状态机 |
| 邻居发现 | 直接邻居与链路成本由本机接口提供；端点立即发现 up/down | 不模拟 ARP、Hello、keepalive 或检测误差；远端仍必须等路由消息传播 |
| 坏链路中的在途消息 | 给链路增加内部代次，跨越断开/修复的旧消息丢弃 | 用于避免恢复后“复活”已经丢失的旧消息，是传输仿真规则；不是 RIP 标准字段 |
| 顺序检查 | 向量附带发送方递增 `seq`，玩家可拒绝旧序号 | 是教学扩展，基础 RIPv2 并不提供这里的序号机制；不是对所有协议的描述 |
| 超时与更新 | 玩家选择何时发送、何时让缓存失效；示例同时演示周期/触发更新 | 不实现 RIP 的完整垃圾回收、触发抑制与报文格式；省略某项不应被当成完整生产实现 |
| 数据包 | 一个观察包，每时隙最多转发一跳，TTL=12；经过链路的教学代价单独累加 | 不模拟流量负载、排队或多流；`None` 允许人为等待而不消耗 TTL，是游戏控制机制 |
| 策略 | 禁止使用某节点作为下一跳，规则同时安装在各本地邻接；影响逐跳通告和转发 | 是简化的节点禁行规则，不是 BGP 路径属性或复杂的跨域策略体系 |
| 攻击 | 特定节点通过同一消息队列宣告到 F 距离 0，并将收到的数据包丢弃 | 固定的虚假通告/黑洞模型，不模拟密码学、密钥管理、真实攻击或设备漏洞 |
| 来源标记 | 每条消息和邻接有模拟器设置的 authenticated 布尔值 | 它不是完整认证协议，也不证明内容为真；测试明确展示已认证节点仍可说谎 |
| 收敛验收 | 观察器核对正常且获准节点到 F 的表与合法最短路，再检查有限稳定窗口 | 验收借助全局信息，仅游戏观察器可见；节点 `solve(ctx)` 不获得该结果，有限稳定窗口不是永久正确证明 |
| 故障后的重试 | 失败重放同一事件起点；成功才提交状态并自动触发新事件 | 这是可比较的实验机制，真实网络不会因为失败而回滚 |
| Python 执行 | 各路由器的函数命名空间、表和显式状态彼此分开；子进程总运行超时 6 秒 | 这是逻辑模型，不是 OS 安全沙箱，也不能防止可信程序主动读取外部信息 |

## 可复现观察

`py -3 demo_replay.py --seed 20261028 --output reports/my_replay.json` 会运行已知的旧/新参考算法，导出实际消息及逐时隙到 F 的表项。交付中的 `reports/scenario_trace.json` 是本次生成的结果。

`test_count_to_infinity_is_a_computed_sequence` 使用 A—B—F 线路，先收敛再断开 B—F。朴素向量交换使 A 到 F 的距离经历 `2, 4, 4, 6, 6, 8, 8, 10, …, 16`。这些数值来自消息与计算，不是脚本预写动画。启用反向毒化后，A 与 B 在两个传播时隙内撤销这条路由。另一个测试使用三角拓扑，保留反向毒化仍可观察 A→B→C→A。

本轮未加入声音、账号、成就、打卡、磁盘存档、云服务、生产路由守护进程或共享代码安全隔离。

### 表中环路观察器
每帧的 routing_loops 只读检查到 F 的有限度量和可用下一跳，输出规范化的循环（例如 A→B→A）。它不注入探测包、不修改路由表，也不进入 solve(ctx)。控制面存在环路不等于本次探测包一定经过该环路；一次距离增加也不能单独证明计数到无穷。
