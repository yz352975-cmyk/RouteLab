RouteLab / Python 动态网络与跨网运营 v0.4
====================================
本项目由 OpenAI Codex 实现并持续迭代开发，依据项目发起者的需求与反馈完成。
这是在附件 v0.2 上继续开发的桌面小游戏，仍使用 Python 3.10+ 与自带 Tkinter。
不需要 Unity、pip 包、服务器或联网。所有节点和链路都是虚构的。

Windows 10 / 11 启动
--------------------
1. 安装 python.org 的标准 Python 3.10 或更新版本，保留 Tcl/Tk 组件和 Python Launcher。
   下载：https://www.python.org/downloads/windows/
2. 解压整个 ZIP 到一个普通文件夹；不要在压缩包内直接打开，也不要只复制 RouteLab.py。
3. 双击“启动RouteLab.bat”，从新手引导开始游戏。
4. 命令行启动：进入项目目录，运行 py -3 RouteLab.py
   指定可复现的会话：py -3 RouteLab.py --seed 20261028
5. 若找不到 py，启动器会尝试 python；请确认该命令指向 Python 3.10+。
6. 如果提示缺少 _tkinter，修复 Python 安装，勾选 Tcl/Tk and IDLE。
7. 若双击窗口消失，在目录地址栏输入 cmd 回车，再运行上述命令查看错误。

第一次体验
----------
- 左边是拓扑，右边是 Python 编辑器，下面是运行日志。
- 初始进入四步 Dijkstra 编程引导：邻居表→费用账本→更新距离→还原路线。先读当前任务，点“拆开看”逐条查看思路，需要 Python 结构时点“代码提示”。在 TODO 下方补写代码，保留临时返回标记。点击“检查本步”或按 Ctrl + Enter，通过后点击“继续写下一步”。最后点击“检查并发送”，看包裹沿自己的路线送达，再进入新的网络事件。
- 第一次写 Python 时可以点“拆开看”，一条一条读当前练习的例子。输入 fo 时，编辑器上方会预览循环写法；按 Tab 接受，也可以继续自己输入。引导中，冒号后按回车会自动缩进，Tab 在没有候选时输入四个空格。
- 先播放数据包动画，再自动发生下一次网络事件；没有关卡列表或下一关按钮。
- 分布式事件仍然写 def solve(ctx)，但增加了两个阶段：
    update：处理本地 inbox / table / state，返回 table 与按邻居分别组织的 advertise。
    forward：返回下一跳字符串，或 None 等待消息继续传播。
- 代码不会随事件改变。失败不会推进；改代码后从同一事件起点重试。
- “参考代码”只在你明确点击并确认后替换编辑器；通常可先用“提示”观察根因。
- 诊断观察器可选择 A～G、拖动消息时间线、查看消息序号/距离/发送与送达时间。
- 会话种子与事件种子显示在诊断区。默认会话种子为 20261028。
- “重置世界”使用同一种子重新开始，并保留编辑器代码；需要时手动载入开场参考代码。
- 本版没有磁盘存档或编辑器自动保存。退出前请把自己的代码复制到 .py 文件中。

本轮真正新增的玩法
------------------
- 每台路由器独立维护路由表和 Python 状态，初始只知道自身与直接链路。
- 距离向量从玩家 advertise 输出进入真实的仿真队列；消息经过延迟后才进入邻居 inbox。
- 周期更新、触发更新、消息超时、反向毒化与乱序处理由玩家代码实现。
- 故障保留旧表、邻居通告和在途消息。坏消息需要逐跳传播，不会全网瞬时刷新。
- 数据包可真实重复经过节点，直到送达或 TTL 耗尽，不再用 visited 过滤冒充环路模型。
- 分区后传播不可达，随后修复；策略与错误通告也通过同一套消息模型影响路由。
- 成功要求数据包送达、正常节点到 F 的路由表正确，并通过有限的稳定观察窗口。
  这项全局验收仅属于观察器，不会提供给 solve(ctx)。

验证与重放
----------
完成固定的距离向量实验与首次随机事件后，会接手云渡区域网的十次跨网调度。
观察彩色站点、箭头与“运营商关系”；按当前合同规划一条合规路线。地图边上标注费用与毫秒数。
“网络状态”列出逐链路明细。暂停、单步及倍速用于回放；折叠诊断可给地图留出更多空间。
成功完成第十次跨网调度并看完传输动画后，主线自动进入网络安全事件 S1「新服上线」，沿用编辑器中的代码。
编辑器上方的三步引导会随操作更新：先观察无策略回放，再点“看起手写法”学习给已有 solve 添加服务分支，最后运行策略并对比正常登录和积压。示例可复制，编辑器由玩家自行修改。
先看无策略基线，暂停后拖动地图下方的时间线。点 B、C 或 D 可以跟踪单个入口的请求、重试和在服务器队列中的积压；点 F 恢复全网视图。“查看本轮 ctx”对应当前窗口。
S1 成功后自动进入 S2「活动开场」。先运行保留下来的策略，核对正常登录、误封和漏放，再从活跃会话数和重试趋势寻找修改思路。S2 成功后恢复距离向量随机事件；其间每隔两个网内事件发生一次跨网变更。后续合同沿用此前条款。接口见 docs/API.md。
默认后端 trusted 仅用于可信本地代码。显式指定 --backend isolated 时，在隔离后端部署并通过独立审阅前，执行会被拒绝。
双击 test_RouteLab.bat，或在项目目录运行：
    py -3 verify.py
    py -3 -m unittest discover -s tests -v
生成 reports/test_output.txt 与 reports/test_results.json。
有图形桌面时执行真实 Tk GUI 测试；无显示服务时明确报告 GUI 测试跳过。
仅重放内置参考实验：
    py -3 demo_replay.py --seed 20261028 --output reports/my_replay.json
这个命令行演示会显式比较旧/新参考算法，不会修改游戏编辑器。

文件导航
--------

- DELIVERY_REPORT.md：本次实际验证结果与尚未覆盖的平台限制。

- WORK_开发任务书.md：原始任务书，保留原文。

运行玩家代码的边界
------------------
runner.py 在独立子进程内运行代码，GUI 默认等待最多 6 秒；print 输出会被单独收集。
这不是安全沙箱：代码仍能导入模块、读写文件或访问网络。只运行自己写/信任的代码。
不要直接运行别人分享的任意代码；本版没有为此提供 OS 级隔离。
